## 1. 先明确目前做到哪里

项目已形成“板端检测 + Windows 实时监护”的原型系统。板端使用确定性规则状态机，完成点云处理、单目标跟踪、跌倒候选、疑似、确认及站起恢复；PC 用于显示、声音报警、配置、设备自检和日志留证。当前实时检测没有使用机器学习模型。

历史上做过侧装到顶装、横向跟踪、候选短时丢失容错、双位置参考恢复等优化。已有受控测试记录，不能据此声称已达到跨场地、跨人群的产品验收标准。联网与远程告警尚未接入。完整 SDK 不等同于已经安装好 CDK；换电脑仍需准备开发工具和驱动。

常用命令：

```text
fall_config
fall_height
mmwc stop
fall_height 310
mmwc start
```

设置高度应等到返回 `FALL_HEIGHT set=310cm saved=1` 后再启动雷达。高度可配置不代表俯角、ROI 和规则阈值也会自动改变。

## 5. 判断策略与代码定位

`src/fall_pipeline.c/.h` 负责运动/存在点云融合输入、世界坐标转换、ROI/SNR、聚类和单目标关联。`src/fall_rule.c/.h` 维护时间窗口和状态机，`src/prj_config.h` 定义默认参数，`src/mmw_app_entry.c` 连接雷达回调、状态输出和配置命令。

核心流程：

```text
运动点云 + 存在点云
  -> 坐标转换 / ROI / SNR
  -> 聚类 / 单目标跟踪 / 短时保持与重捕获
  -> 下降量 + 运动证据 + 低位持续
  -> 内部候选 -> 疑似 -> 确认并保持报警
  -> 关联目标持续站起 -> 恢复
```

| 阶段 | 当前关键条件（以源码为最终依据） |
| --- | --- |
| 内部候选 | 最近 3500ms 目标高度下降至少 80cm；近期速度至少 45cm/s 或运动点数至少 20；当前高度不超过 55cm，700ms 窗口至少 92% 高度样本处于该低位 |
| 疑似 | 已有候选；当前有新鲜目标且高度不超过 40cm；700ms 有足够时间覆盖，至少 3 个有效连续样本，终态低位比例至少 92% |
| 确认 | 疑似后重新计时至少 1200ms；至少 6 个有效连续样本，低位比例至少 70%；当前仍有新鲜低位目标；相对跌前锚点的最大水平位移至少 30cm |
| 候选容错 | 跟踪 HOLD 在 800ms 内可保留低位连续性；当前新鲜标志仍反映真实观测，长缺口不能无限累积证据 |
| 确认保持 | 不会因单帧丢目标或报警弹窗消失就自动清除确认状态 |
| 恢复 | 新鲜目标高度至少 85cm，持续至少 1000ms；距确认低位中心不超过 80cm，或距跌前锚点不超过 100cm |

`CANDIDATE` 是内部过程，不要假设它有独立的串口数值状态。对外 `FALL_EVENT` 主要为 `suspected`、`confirmed`、`recovered`。目标高度是选中点云簇的统计中心高度，不是人体身高，也不是单个最高点。

`fall_detection/rule_detector.py` 是历史 PC 离线规则实现，不能不经对照就视为与最新板端逐条一致；`pc_ml` 下的模型也未参与现有实时告警。

## 6. 先运行，再开发

打开 `project/releases/20261027-144901/MRS6240-Fall-Monitor/`：

## 7. PC 源码环境与重新生成 EXE

安装 Windows x64 Python 3.12（本机打包版本 3.12.10），在 `project/` 下执行：

```powershell
py -3.12 -m venv .build\portable-env
.\.build\portable-env\Scripts\python.exe -m pip install -r ..\environment\requirements-pc-lock.txt
.\.build\portable-env\Scripts\python.exe -m fall_detection.serial_event_live_visualizer --source device --ui-mode engineering --serial-port COM3
```

开发环境安装依赖默认需要网络，包内没有另附 Python 3.12 安装程序、完整离线 wheel 仓库或 CDK 安装程序；不要把此包描述为“全新电脑无需安装即可重新编译所有源码”。SDK 内的 WinPython 是厂商工具配套运行时，与 PC 上位机环境分开。

重新打包 EXE 时可显式使用随包的 CH347 本地 DLL：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\windows\build_portable.ps1 -Ch347Dll .\releases\20261027-144901\MRS6240-Fall-Monitor\_internal\hardware\CH347DLLA64.dll
```

源码测试：

```powershell
.\.build\portable-env\Scripts\python.exe -m pytest -q fall_detection\tests\test_runtime_paths.py fall_detection\tests\test_device_source.py fall_detection\tests\test_serial_event.py fall_detection\tests\test_serial_event_live_visualizer.py
```

不要直接复制开发者电脑上的桌面 `.lnk`：它们使用绝对路径。接手人在新位置为 EXE 自建快捷方式即可。

本机使用 CDK App 2.24.11，工具链管理名称 `XTGccElfNewlib / V3.1.0 / R`，目标为 MRS6240-P2512 CPUF，工程配置名 `psdf`。工具链本体已保存在 `toolchains/` 中；CDK IDE 需要对方按其正常安装流程另行准备，并在 CDK 中注册/选择对应工具链路径。

1. 将交接包解压到较短路径，例如 `D:/MRS6240-Handover/`。
2. 用 CDK 打开 `project/SDK/Software_Kit/02_SDK/psdf_sdk/project/mmwave/mmwave_application/Falldown/cdk_6240_cpuf/project.cdkws`，或载入对应 `project.cdkproj`。
3. 选择 `Posture_MRS6240_P2512` / `psdf`，确认工具链指向已安装/注册的 XTGccElfNewlib。
4. 通过 CDK 重新生成构建文件并编译，检查后处理和镜像打包输出，而不只看 C 编译通过。
5. 新镜像位于该子工程 `output/mrs6240_p2512.img`。原镜像已另存 `firmware/current/`，重新编译前继续备份，不覆盖旧基线。
